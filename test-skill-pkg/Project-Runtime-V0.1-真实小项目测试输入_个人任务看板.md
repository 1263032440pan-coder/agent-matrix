# 小型测试项目：个人任务看板 Web 应用

> 用途：用于验证 Project Runtime V0.1 在真实小项目中的完整执行能力。  
> 建议绑定 Project Method Skill：`software-project-delivery`。  
> 本文仅作为用户输入的项目需求素材，不等同于完整需求文档、架构文档或开发文档。

---

## 1. 项目名称

个人任务看板 Web 应用

## 2. 项目背景

希望开发一个简单的个人任务管理系统，用于记录和管理日常待办事项。

目前存在的问题：

- 任务容易遗漏；
- 无法快速查看当前进行中的事项；
- 已完成任务和未完成任务混在一起；
- 缺少优先级和截止日期管理；
- 无法方便地按照状态或优先级筛选任务。

希望通过一个轻量级 Web 应用解决上述问题。

## 3. 项目目标

建设一个可以在本机运行的个人任务看板。

用户可以：

```text
创建任务
查看任务
修改任务
删除任务
调整任务状态
设置优先级
设置截止日期
搜索和筛选任务
```

系统需要能够持久化保存任务数据，重新启动后数据不能丢失。

## 4. 目标用户

本项目仅面向单个本地用户。

当前版本明确不做：

```text
用户注册
登录
多用户
组织/部门
复杂权限体系
```

## 5. 核心功能

### 5.1 创建任务

任务至少包含：

```text
任务标题
任务描述
任务状态
优先级
截止日期
创建时间
更新时间
```

其中：

- 任务标题：必填；
- 任务描述：可选；
- 截止日期：可选。

### 5.2 任务状态

固定为：

```text
TODO
IN_PROGRESS
DONE
```

### 5.3 优先级

固定为：

```text
LOW
MEDIUM
HIGH
```

默认：

```text
MEDIUM
```

### 5.4 任务列表

至少展示：

```text
任务标题
任务状态
优先级
截止日期
更新时间
```

### 5.5 任务详情

点击任务后可以查看完整任务信息。

### 5.6 编辑任务

允许修改：

```text
任务标题
任务描述
任务状态
优先级
截止日期
```

### 5.7 删除任务

删除前必须二次确认。

### 5.8 搜索

按照任务标题进行关键词搜索，支持部分匹配。

### 5.9 筛选

至少支持：

```text
任务状态
优先级
```

搜索和筛选可以组合使用。

### 5.10 统计

页面顶部展示：

```text
任务总数
待处理数量
进行中数量
已完成数量
```

统计结果必须与真实数据一致。

## 6. 页面要求

本项目只要求一个主要页面。

建议结构：

```text
┌────────────────────────────────────────────┐
│               个人任务看板                 │
├────────────────────────────────────────────┤
│ 总数 | 待处理 | 进行中 | 已完成            │
├────────────────────────────────────────────┤
│ 搜索框 | 状态筛选 | 优先级筛选 | 新建任务  │
├────────────────────────────────────────────┤
│              任务列表区域                  │
├────────────────────────────────────────────┤
│                分页区域                    │
└────────────────────────────────────────────┘
```

新建和编辑任务可使用弹窗或抽屉，具体形式由系统原型阶段确定。

## 7. 基本业务流程

### 7.1 创建任务

```text
用户点击新建任务
→ 填写任务信息
→ 提交
→ 系统校验
→ 保存任务
→ 刷新任务列表和统计信息
```

### 7.2 修改任务

```text
用户选择任务
→ 打开编辑
→ 修改内容
→ 提交
→ 系统校验
→ 更新任务
→ 刷新任务列表
```

### 7.3 完成任务

```text
用户将状态改为 DONE
→ 系统保存
→ 已完成数量增加
→ 当前任务状态更新
```

### 7.4 删除任务

```text
用户点击删除
→ 二次确认
→ 用户确认
→ 删除任务
→ 刷新列表和统计数据
```

## 8. 数据持久化要求

必须使用真实持久化存储。

要求：

```text
应用关闭并重新启动后
任务数据仍然存在
```

禁止仅使用：

```text
前端内存数据
Mock 数据
临时 JSON 数据模拟数据库
```

具体数据库技术由开发设计阶段唯一确定。

## 9. 接口要求

前端与后端通过 API 通信。

至少支持：

```text
创建任务
查询任务列表
查询任务详情
修改任务
删除任务
获取任务统计
```

具体 URL、HTTP Method、Request/Response Schema、Error Code 由开发设计阶段确定。

## 10. 异常处理要求

至少处理：

```text
任务标题为空
任务不存在
非法任务状态
非法优先级
后端接口失败
数据库操作失败
```

前端需要给用户明确提示。

## 11. 非功能要求

### 11.1 运行环境

主要目标：

```text
本地单机运行
```

不要求：

```text
云部署
Kubernetes
高可用
分布式架构
```

### 11.2 性能

测试数据量：

```text
1000 条任务以内
```

普通列表查询应正常、流畅。

### 11.3 安全

当前版本不涉及敏感数据，不要求登录与权限体系，但后端必须进行基本输入校验。

### 11.4 可维护性

前后端代码结构清晰，不允许把所有功能放进单个超大文件。
