# 软件项目交付方法（小型本地 Web 应用）

本方法定义一个小型软件项目从输入材料到最终交付的**九个阶段**。每个阶段说明：目标、输入、产出、验收要点。执行者（Worker）按阶段推进，每个阶段的产出（Artifact）需通过 Gate 验收后才进入下一阶段。

**核心原则（优先级从高到低）**：

1. **项目输入材料的明确约束永远优先**——本方法提供流程与模板，不得覆盖用户材料中写明的范围、禁止项、验收标准；
2. **技术选型唯一化**——进入开发前必须形成唯一技术栈（版本锁定），禁止"A 或 B 均可"；
3. **真实持久化**——数据层必须是真实数据库，禁止内存/Mock/临时 JSON 模拟；
4. **范围纪律**——明确不做的功能绝不做，不得因"通常需要"而私自增加；
5. **完成判定靠证据**——项目完成需要 Final Gate 检查开发/测试/交付/使用文档齐备，而非"代码写完"。

---

## 阶段 1：项目理解（Project Understanding）

**目标**：准确识别项目类型、规模、目标用户与关键约束。

**要点**：
- 判断项目类别（如：小型软件开发项目 / 内容项目 / 数据项目）；
- 提取明确约束清单：必须做的、明确不做的、技术约束、运行环境；
- 识别目标用户与使用场景（单用户本地 / 多人 / 服务端部署）；
- 列出输入材料中已有的信息与**缺失**的信息（不得伪造已有 Artifact）。

**产出**：项目理解摘要（类型判定 + 约束清单 + 信息缺口清单）。

**验收**：类型判定正确；约束清单覆盖输入材料全部"必须/不做/禁止"条目。

## 阶段 2：需求基线（Requirements Baseline）

**目标**：把输入材料整理为结构化、可验收的需求文档。

**要点**：
- 功能需求逐条编号（FR-001 起），每条含：描述、优先级（本期必须/不做）、验收标准；
- 非功能需求单列（性能、运行环境、安全、可维护性）；
- 边界场景清单（空输入、非法值、不存在资源、接口失败）；
- 与输入材料逐条对照，确认无遗漏、无擅自增加。

**产出**：需求文档（含功能清单 + 非功能清单 + 边界场景 + 验收清单）。

**验收**：输入材料每一条"必须实现"均对应 FR 编号；"明确不实现"清单完整照搬。

## 阶段 3：解决方案（Solution）

**目标**：给出整体方案——做什么、怎么分层、如何演进。

**要点**：
- 方案概述（一段话说清系统做什么）；
- 技术选型**唯一确定**：前端框架+版本、后端框架+版本、语言+版本、数据库+版本、ORM、测试框架、构建与启动方式——每一项一个答案；
- 分层结构（前端 / 后端 API / 数据层）与职责边界；
- 关键决策记录（为什么这么选，一句话理由）。

**产出**：解决方案文档（含唯一技术栈表 + 分层说明）。

**验收**：技术栈表无"A 或 B 均可"类条目；选型与项目约束一致（如本地单机运行）。

## 阶段 4：原型设计（Prototype）

**目标**：确定页面结构与交互形态，开发前可视化。

**要点**：
- 页面布局线框图（文本框图即可，标注区块职责）；
- 关键交互流（新建/编辑用弹窗还是抽屉、删除二次确认形式）；
- 状态与筛选控件的呈现方式。

**产出**：系统原型图（页面结构 + 交互说明）。

**验收**：覆盖输入材料的页面要求；交互形态唯一确定。

## 阶段 5：架构设计（Architecture）

**目标**：确定模块划分、数据模型与接口契约。

**要点**：
- 模块划分图（禁止单文件大杂烩——前端组件/页面分层，后端 router/service/model 分层）；
- **数据模型**：表结构定义（字段、类型、约束、索引），与需求字段一一对应；
- **API 契约**：每个接口的 Method + URL + Request Schema + Response Schema + Error Code（覆盖增删改查 + 统计）；
- 业务流程图（创建/修改/完成/删除主流程 + 异常分支）。

**产出**：系统架构文档（模块图 + 数据模型 + API 契约 + 流程图）。

**验收**：API 契约覆盖全部 FR；数据模型支持全部字段与筛选/搜索需求。

## 阶段 6：开发实现（Development）

**目标**：按架构实现可运行的系统。

**要点**：
- 按模块实现，先数据层 → 后端 API → 前端页面；
- 输入校验（标题必填、状态/优先级枚举校验、日期格式）；
- 错误响应统一格式（明确 Error Code 与 message）；
- 前端接口失败必须有用户可见提示；
- 代码结构遵循架构文档的模块划分。

**产出**：项目源码 + 开发文档（模块清单 + 启动方式 + 目录结构说明）。

**验收**：按使用文档可本地启动；核心 API 手工调用通过；无"TODO 未实现"残留。

## 阶段 7：测试验证（Testing）

**目标**：自动化测试 + 端到端闭环证明。

**要点**：
- 后端测试：创建/查询/修改/删除 + 非法状态 + 非法优先级 + 任务不存在 + 统计接口；
- 前端测试：页面加载、列表展示、增删改、搜索筛选、统计展示、失败提示；
- E2E 至少一条真实闭环：启动 → 创建 → 查询 → 改 IN_PROGRESS → 改 DONE → 查统计 → 删除 → 确认不存在；
- 测试报告：用例清单 + 执行结果 + 已知问题（如有）。

**产出**：测试用例 + 测试代码 + 测试报告。

**验收**：后端/前端核心测试全过；E2E 闭环通过；无阻塞级缺陷。

## 阶段 8：交付打包（Delivery）

**目标**：形成完整交付物集合。

**要点**：
- 按交付清单核对：源码、解决方案、需求文档、原型图、流程图、架构文档、开发文档、测试报告、交付文档、使用文档；
- 交付文档：版本说明 + 交付物清单 + 已知限制；
- 使用文档：环境要求 + 安装步骤 + 启动命令 + 功能使用说明（面向最终用户，非开发者）。

**产出**：交付文档 + 使用文档（补齐清单缺口）。

**验收**：交付清单十项齐备；使用文档按步骤能启动系统。

## 阶段 9：Final Gate（完成判定）

**目标**：证据驱动的项目完成检查。

**要点**（全部满足才算 Project Completed）：
- [ ] 开发完成（源码可启动）
- [ ] 测试通过（后端 + 前端 + E2E）
- [ ] 交付文档齐备（十项清单）
- [ ] 使用文档可用（照做能跑起来）
- [ ] 验收标准逐条核对（对照需求文档的验收清单）

**产出**：Final Gate 检查记录（逐项勾选 + 证据引用）。

**验收**：任何一项不满足即回 REWORK，明确指出缺口；**不得因"代码写完"判完成**。

## 与 Project Runtime 的配合说明

- 本方法作为 **PROJECT_METHOD** Skill 参与项目 Playbook 生成：Runtime 应将其阶段映射为项目的 Task Graph（每阶段至少一个 Task，开发/测试阶段可再拆分）；
- **绑定方式**：建议绑定到项目级（scope=TASK_TYPE，覆盖 需求/设计/开发/测试/文档/交付 等任务类型）；
- **不越权**：本方法不拥有 Project State；Worker 执行任务时参考对应阶段的"要点"作为方法指导，产出仍走 Artifact → Gate 验收链路；
- **约束优先级**：项目输入材料（如《个人任务看板》需求）的明确约束 > 本方法模板。若材料已规定页面结构、状态枚举、禁止项，以其为准。
