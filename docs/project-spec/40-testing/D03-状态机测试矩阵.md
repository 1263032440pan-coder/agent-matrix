# D03 Project / Task 状态机测试矩阵

> 目的：为 D03 开发方与检查方提供同一套客观验收依据。
> 状态机事实源：`00-global/03-核心领域模型.md`。本文件不重新定义业务规则，只将规范映射成测试。

## 1. TaskStatus 合法转移测试

以下每一条都必须验证：

```text
请求转移
→ Transition Validation PASS
→ DB 状态更新
→ TASK_STATUS_CHANGED 持久化
→ 关键语义 Event（如适用）持久化
```

| Case | From | To | 预期 |
|---|---|---|---|
| T-V01 | CREATED | READY | PASS |
| T-V02 | CREATED | BLOCKED | PASS |
| T-V03 | CREATED | CANCELLED | PASS |
| T-V04 | READY | RUNNING | PASS |
| T-V05 | READY | BLOCKED | PASS |
| T-V06 | READY | CANCELLED | PASS |
| T-V07 | RUNNING | EXECUTION_DONE | PASS |
| T-V08 | RUNNING | BLOCKED | PASS |
| T-V09 | RUNNING | FAILED | PASS |
| T-V10 | RUNNING | CANCELLED | PASS |
| T-V11 | EXECUTION_DONE | ACCEPTED | PASS，仅 Gate PASS |
| T-V12 | EXECUTION_DONE | REWORK | PASS，仅 Gate FAIL / Rework Decision |
| T-V13 | REWORK | READY | PASS |
| T-V14 | REWORK | CANCELLED | PASS |
| T-V15 | BLOCKED | READY | PASS |
| T-V16 | BLOCKED | CANCELLED | PASS |
| T-V17 | FAILED | READY | PASS，Retry |
| T-V18 | FAILED | REWORK | PASS |
| T-V19 | FAILED | CANCELLED | PASS |

## 2. TaskStatus 非法转移测试

每个非法转移都必须验证：

```text
INVALID_STATE_TRANSITION
DB 状态不变
不产生 TASK_STATUS_CHANGED 成功事件
存在错误日志/审计记录
```

最低必测：

| Case | From | To | 预期 |
|---|---|---|---|
| T-I01 | CREATED | RUNNING | REJECT |
| T-I02 | CREATED | ACCEPTED | REJECT |
| T-I03 | READY | ACCEPTED | REJECT |
| T-I04 | RUNNING | ACCEPTED | REJECT |
| T-I05 | BLOCKED | ACCEPTED | REJECT |
| T-I06 | FAILED | ACCEPTED | REJECT |
| T-I07 | ACCEPTED | REWORK | REJECT |
| T-I08 | ACCEPTED | READY | REJECT |
| T-I09 | CANCELLED | READY | REJECT |
| T-I10 | CANCELLED | RUNNING | REJECT |

此外应参数化遍历所有 `From x To` 组合，确保只有 `03-核心领域模型.md` 列出的边存在。

## 3. Gate 硬规则测试

- [ ] Worker 直接请求 `RUNNING -> ACCEPTED` 被拒绝。
- [ ] Worker 返回完成结果只允许 `RUNNING -> EXECUTION_DONE`。
- [ ] Gate PASS 才允许 `EXECUTION_DONE -> ACCEPTED`。
- [ ] Gate FAIL 导致 `EXECUTION_DONE -> REWORK`。
- [ ] Gate BLOCKED / 等待人工输入时 Task 保持 `EXECUTION_DONE`，等待原因进入 GateResult / Issue / ManualAction / UserInputRequest。

## 4. Dependency 测试

给定：

```text
Task B HARD depends on Task A
```

验证：

| Task A 状态 | Task B 是否可因依赖满足进入 READY |
|---|---|
| CREATED | 否 |
| READY | 否 |
| RUNNING | 否 |
| EXECUTION_DONE | 否 |
| REWORK | 否 |
| BLOCKED | 否 |
| FAILED | 否 |
| CANCELLED | 否 |
| ACCEPTED | 是 |

## 5. Resource Governor 测试

给定 Task=`READY`，Resource Governor 返回：

```text
DEFER_RESOURCE
```

验证：

- [ ] Task 仍为 `READY`。
- [ ] 不转 `BLOCKED`。
- [ ] 不转 `FAILED`。
- [ ] 产生 `WORKER_DISPATCH_DEFERRED`。
- [ ] 资源释放后可再次 Dispatch 并 `READY -> RUNNING`。

## 7. ProjectStatus 非法转移最低测试

- [ ] CREATED -> ACTIVE：REJECT。
- [ ] ACTIVE -> COMPLETED：REJECT。
- [ ] BLOCKED -> COMPLETED：REJECT。
- [ ] COMPLETED -> ACTIVE：REJECT。
- [ ] CANCELLED -> ACTIVE：REJECT。
- [ ] 任意 `ProjectStatus=FAILED` 输入：Schema / Domain Validation REJECT（V0.1 未定义该状态）。

## 8. 事务一致性测试

- [ ] 状态写入失败时 Event 不得成功提交。
- [ ] Event 持久化失败时状态事务必须回滚。
- [ ] `expected_from_status` 与 DB 当前状态不一致时拒绝，避免并发覆盖。
- [ ] 同一 `command_id` 重复提交应幂等或确定性拒绝，不得产生重复状态推进。
