# 04 全局接口与事件规范

## Project / Task State Transition Contract

`ProjectStatus`、`TaskStatus` 及合法转移表以：

```text
00-global/03-核心领域模型.md
```

为唯一事实源。本文件只定义“如何请求状态变化、谁可以提出、成功后发什么事件、非法时如何返回错误”。

### 1. 禁止公开任意状态写接口

不得提供以下形式的通用接口：

```text
PUT /tasks/{id}/status
PATCH /projects/{id} { status: ... }
```

原因：调用方不应绕过状态机直接指定目标状态。外部 API 应表达业务动作，例如 cancel、resume、confirm；内部模块通过 Transition Command 请求 Core 执行状态迁移。

### 4. 状态转移请求来源

| 来源 | 可提出的典型转移 | 说明 |
|---|---|---|
| Bootstrap / State Discovery | Project `CREATED -> INITIALIZING -> ACTIVE/BLOCKED` | 只提出请求，Core 提交 |
| Task Graph / Frontier | Task `CREATED -> READY/BLOCKED` | 根据依赖、输入和逻辑前置条件 |
| Scheduler | Task `READY -> RUNNING` | Worker 成功 Dispatch 后 |
| WorkerRuntimeAdapter | Task `RUNNING -> EXECUTION_DONE/BLOCKED/FAILED` | Worker 结果只能作为 Proposal/Command 输入 |
| Gate Core | Task `EXECUTION_DONE -> ACCEPTED/REWORK` | 只有 Gate Core 能触发 ACCEPTED |
| Replanner / Issue Resolver | Task `BLOCKED/REWORK/FAILED -> READY` | 满足恢复条件后 |
| Completion Service | Project `ACTIVE -> COMPLETING -> COMPLETED/ACTIVE/BLOCKED` | 按 Delivery Contract 与 Final Gate |
| User / Automation Controller | Cancel / Resume 等业务动作 | 仍必须走 Core Transition Validation |
| Extension / Plugin | 仅 Proposal | 永远不得直接提交状态 |

### 5. 状态事件统一信封

所有成功状态变化必须至少持久化一个统一状态事件：

```text
event_id
event_type
project_id
entity_type
entity_id
from_status
to_status
reason_code
actor_type
actor_id
correlation_id
causation_id
occurred_at
```

基础事件：

```text
TASK_STATUS_CHANGED
PROJECT_STATUS_CHANGED
```

关键语义事件同时发出：

```text
TASK_CREATED
TASK_READY
TASK_STARTED
TASK_EXECUTION_DONE
TASK_BLOCKED
TASK_FAILED
TASK_REWORK_REQUIRED
TASK_ACCEPTED
TASK_CANCELLED

PROJECT_CREATED
PROJECT_INITIALIZING
PROJECT_ACTIVATED
PROJECT_BLOCKED
PROJECT_COMPLETION_STARTED
PROJECT_COMPLETED
PROJECT_CANCELLED
```

### 6. Gate 与状态事件规则

```text
Worker Result = EXECUTION_DONE
→ Task RUNNING -> EXECUTION_DONE
→ TASK_EXECUTION_DONE
→ Gate Evaluate
```

Gate PASS：

```text
EXECUTION_DONE -> ACCEPTED
→ TASK_ACCEPTED
```

Gate FAIL：

```text
EXECUTION_DONE -> REWORK
→ TASK_REWORK_REQUIRED
```

Gate BLOCKED / 等待人工输入：

```text
Task 默认保持 EXECUTION_DONE
GateResult / Issue / ManualAction / UserInputRequest 记录等待原因
```

不得为了表达 Gate 等待而随意创造未在 `03-核心领域模型.md` 中定义的 TaskStatus。

### 7. Resource Deferred 规则

```text
READY + DEFER_RESOURCE
```

只产生：

```text
WORKER_DISPATCH_DEFERRED
```

Task 仍保持 `READY`。资源不足不是 Task `BLOCKED`，也不是 `FAILED`。

### 8. 非法状态转移错误

统一错误：

```text
INVALID_STATE_TRANSITION
```

建议响应：

```json
{
  "code": "INVALID_STATE_TRANSITION",
  "entity_type": "task",
  "entity_id": "T001",
  "from_status": "RUNNING",
  "to_status": "ACCEPTED",
  "reason": "Gate must pass before ACCEPTED",
  "correlation_id": "..."
}
```

要求：

- HTTP/API 层建议返回 `409 Conflict`；
- 内部调用返回确定性的 Domain Error；
- 不提交状态事务；
- 不发送 `TASK_STATUS_CHANGED` / `PROJECT_STATUS_CHANGED` 成功事件。
