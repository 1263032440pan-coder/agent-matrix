- `TaskStatus` 已冻结；
- `ProjectStatus` 已冻结；
- 合法转移表已冻结；
- 终态语义已冻结；
- `EXECUTION_DONE != ACCEPTED` 已进入全局规范；
- 状态变更唯一入口与 Event Contract 已定义；
- `INVALID_STATE_TRANSITION` 判定标准已定义。

如果上述任一项缺失：

```text

```

Coding Agent 不得自行补充状态机业务规则。

## V1.12：D17.5 Skill Runtime Infrastructure

当前实际进度：

```text
D01～D17 = PASS / FROZEN
Current Frontier = D17A
D18 = NOT_STARTED
```

新增正式 Work Package：

```text
WP-039 Skill Runtime Integration
```

D17.5 拆分：

```text
D17A Skill Registry
D17B Skill Package Import + Validation
D17C Skill Resolver + Project Binding
D17D Skill Loader + Worker Execution Integration
```

说明：D17.5 **不开发任何具体领域 Skill**。具体 Project Method / Task Execution / Capability Skill 均由后续用户、组织或 Plugin 提供。

### D17A Gate

- Skill Registry 支持三类 Skill Metadata。
- Registry 为空时系统正常运行。
- Project 可绑定明确 Skill 版本。
- Disabled/Invalid Skill 不参与自动 Resolution。

### D17B Gate

- 可从目录/ZIP 导入合法声明式 Skill Package。
- `SKILL.md` Frontmatter 可解析并校验。
- Path Traversal / 非法文件类型 / Schema 错误被拒绝。
- V0.1 不执行包内脚本。

### D17C Gate

- Resolution 规则优先。
- Required Skill 缺失时不 Dispatch，但不将 Task 判 FAILED。
- Optional Skill 缺失时允许 `NO_SKILL_REQUIRED`。
- 只有完全等价候选才允许 LLM tie-break。

### D17D Gate

- Resolved Skill 可由 Loader 装配成最小 SkillExecutionContext。
- Worker 可在 Work Package 中获得 Skill Context。
- Worker Result 可追踪实际 skill_id/version/hash。
- Skill Loader / Skill 内容不能直接修改 Project/Task State。
- UI 只做最小增量：可观察当前 Skill、版本、Resolution Reason。

D17A～D17D 全部 PASS 后才进入 D18。
