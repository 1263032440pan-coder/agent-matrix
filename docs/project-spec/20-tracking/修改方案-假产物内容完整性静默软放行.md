# 修改方案：假/损坏产物内容完整性校验 + 返工 nudge + 静默软放行

> 版本：2026-10-31（修订 3）  
> 前置：SYS-138～140（预算/返工用尽软放行）；V1.6d 冻结校验脚本；令牌 Stop；交付清单 match  
> 状态：**已拍板草案（待实施）**  
> 触发：工作区出现「扩展名对齐、内容损坏/明文占位/魔数不符」的假产物；存在性闸放行 → 节点 ACCEPTED，用户误以为齐套。  
> 目标：  
> 1. **校验能检出**损坏/假后缀文件（**不限** pptx/png，按后缀族覆盖交付常见类型）；  
> 2. **先通知模型返工**（复用 Stop 返工轮次）；  
> 3. 仍失败则 **软放行不 FAILED、不卡整图**；  
> 4. **节点 UI 不展示**该类最终软放行缺口（审计可见）。

---

## 一、问题定性

### 1.1 现状

| 层 | 行为 | 结果 |
|--|--|--|
| 清单 `match` / 令牌 Stop | 只认路径+扩展名+槽目录/前缀 | 明文占位写成 `xxx.pptx` 也算齐 |
| Gate `file` 校验器 | 有 artifact / 文件即 PASS | 假/损坏文件照样过 |
| 软放行（SYS-138） | 令牌/清单**缺失**时带 `delivery_gap` ACCEPTED | **会在节点上屏**（徽标+详情） |

实测样本（项目 5 / 任务 34～36）：

- `解决方案介绍.pptx` ≈228B，内容为 `This is a placeholder...`（非 OOXML ZIP）  
- 清单 `d1` → `matched`；收口令牌因过载拆分几乎不含 PPT；Gate PASS → ACCEPTED  

「有 `.pptx` 路径但文件损坏」≠「缺文件」：存在性已满足，缺的是**内容合法性**。

### 1.2 需求边界（本次 · 已拍板）

| 要 | 不要 |
|--|--|
| Stop 阶段**检出**假/损坏/魔数不符文件 | 因内容不合格直接 **FAILED** 卡死下游 |
| **返工 nudge 通知模型**补生成（限次） | 无限返工或空转写占位 |
| 限次后仍坏 → **软放行 ACCEPTED** | 在**流程节点**上展示该类最终软放行红标 |
| 运行动态可见返工提示（驱动修复） | 改 Stable Kernel；第三种自动化模式 |
| V0：对 Stop **命中路径**按后缀族做**结构/魔数/非空**完整性（见 §4.1） | V0：PPT 页数≥6、版式审美、文档「写得好不好」等 **skill 级质量** |
| 未知后缀：至少做「非空 + 拒绝明文占位冒充」兜底 | 对未知格式做深度解析 / 杀毒级扫描 |

与 SYS-138 的关系：

| 缺口类 | reason 示例 | 返工 | 最终软放行节点可见性 |
|--|--|--|--|
| 契约缺件（无文件） | `UNMET_AFTER_EARLY_STOP` / `DELIVERY_GAP_AFTER_BUDGET` | ✓×≤3 | **上屏**（不变） |
| 内容完整性（有文件但坏） | `CONTENT_INTEGRITY_SOFT` | ✓×≤3（专用 nudge） | **`audit_only` 静默** |

## 二、目标行为（拍板稿）

```
Worker 拟收工
  → ① 存在性 Stop（令牌 / 清单 match，不变）
        ├─ 不齐 → 既有返工×≤3 → 仍缺 → SYS-138 上屏软放行
        └─ 齐 → ② 内容完整性检查（对本轮扫描到的命中路径）
              ├─ 通过 → 成功 → Gate → ACCEPTED
              └─ 失败 → ③ 完整性返工 nudge（计入同一 _DELIVERY_REPAIR_MAX）
                    │     文案明确：损坏/占位/魔数不符、禁止 write_file 假后缀；
                    │     并按后缀提示正确工具（pptx→slide_generator，
                    │     图→arch_diagram，代码/文档→写出合法内容等）
                    ├─ 未达上限 → continue 工具循环，再验
                    └─ 达上限仍失败
                          → delivery_gap(
                               reason=CONTENT_INTEGRITY_SOFT,
                               soft_accepted=true,
                               ui_visibility=audit_only,
                               problems=[…],
                               integrity_failures=[…]
                             )
                          → Gate PASS_WITH_GAP → ACCEPTED
                          → 下游可 promote（不卡图）
```

| 场景 | 行为 |
|--|--|
| 真缺失（无文件） | **不变**：存在性返工×3 → 上屏软放行 |
| 有命中文件但完整性失败（任意已覆盖后缀） | **本方案**：完整性 nudge×≤3 → 仍失败则**静默**软放行；不 FAILED |
| 返工过程中 | 运行动态可见 nudge / 工具调用（用户能感到在补） |
| 脚本篡改 / 真故障 | **不变**：FAILED |
| 节点徽标 / 选中「软放行」块 | **隐藏** `ui_visibility=audit_only` |
| 概览清单存在性 | V0 保持 `matched`（路径在）；**不上**完整性红叉 |
| 项目收口 | V0 **不**因完整性阻断；审计事件可查；自动补建 **V1** |

原则：

1. **先修后放**：完整性失败必须先给模型限次返工机会。  
2. **调度继续 ≠ 内容可信**：最终静默软放行只保流水线。  
3. **存在性 ⊥ 完整性**：两段检查串联，文案与 reason 分开。  
4. **节点静默、过程可感**：最终徽标静默；返工期靠活动流。  
5. **不 DIRECT_STATE_MUTATE**：经 TaskRun `delivery_gap` + Gate。

## 四、设计

### 4.1 完整性规则（V0）

落点：`project_runtime/procedure/artifact_integrity.py`（纯函数）。

**范围原则**：对本轮 Stop **已命中的每一个相对路径**做检查。  
**先按后缀定族，再套该族规则**——禁止在「未确认文件类型/族」时用统一的「有无实质内容」比例尺去量所有文件。

| 原则 | 说明 |
|--|--|
| 类型优先 | `.py` 短文件可以合法；同长度明文冒充 `.docx`/`.pptx` 必须失败 |
| 二进制族 | 只做魔数/容器结构；外加「头是可打印明文 → 类型不符」 |
| 源码族 | **禁止**用行数/剩余比例判空壳；只拦「空文件」与「整文件等于占位模板」 |
| 文档族 | 空文件；或整文件命中占位模板；**不用**短文长度当质量分 |
| skill 级 | 页数≥6、文笔、测试是否充分 → **不进 Core** |

#### 4.1.1 后缀族规则

| 族 | 后缀（V0） | 判定失败（满足任一） | 不用的规则 |
|--|--|--|--|
| OOXML 演示 | `.pptx` | 非 ZIP / 打不开；缺 `[Content_Types].xml` 或 `ppt/`；体积 &lt; 2KiB；**头为可打印明文**（类型不符） | 行数、页数 |
| OOXML 文档 | `.docx` | 同上，要求 `word/`；明文头同败 | 行数、字数 |
| 位图 | `.png` `.jpg` `.jpeg` `.gif` `.webp` `.bmp` | 魔数与后缀不符；体积过小；明文头 | 「实质内容」比例 |
| 矢量 | `.svg` | 空；无 `<svg`；**整文件**等于占位模板（§4.1.2） | 短 SVG 几何图元不拦 |
| PDF | `.pdf` | 头非 `%PDF`；过小；明文头 | — |
| 压缩包 | `.zip` | 非 ZIP / 打不开 | — |
| 文本文档 | `.md` `.txt` `.rst` `.adoc` | 空或仅空白；**整文件**命中占位模板 | **不因短而败**（短说明合法） |
| 源码/配置 | `.py` `.ts` `.tsx` `.js` `.jsx` `.java` `.go` `.rs` `.toml` `.json` `.html` `.css` 等 | 空或仅空白；`.json` 无法解析；**整文件**等于占位模板 | **严禁** `N≤240` / `R/N` 等长度启发式 |
| Mermaid 源 | `.mmd` | 空；无 diagram 头关键字 | 短 flowchart 不拦 |
| **通用兜底** | 其它已命中后缀 | 大小 0；若后缀落在**已知二进制族别名**却未进上表 → 仍按「声称二进制」做魔数/明文头检查；纯未知文本后缀 → **仅**空文件 | 不对未知文本做占位比例尺 |

#### 4.1.2 「占位 / 类型不符」如何判定（分族，可单测）

**A. 声称二进制族**（pptx/docx/png/jpg/pdf/zip 等）

1. 先跑该族魔数/ZIP 结构；结构失败 → `kind=bad_magic` / `bad_ooxml` 等。  
2. 若结构未过，再看文件头 ≤512B：不可打印字节 &lt; 10% 且可解码为文本，并命中占位锚点或通篇可读英文说明 → `kind=plaintext_disguised_as_binary`（**不必**再算「实质内容比例」：类型已经错了）。  
3. 正例：`This is a placeholder. Run: python…` 写成 `.pptx`。

**B. 源码 / 配置族**

1. `strip()` 后长度为 0 → 失败。  
2. **整文件**（去首尾空白后）与占位模板库**全等或仅差尾随换行**（模板见下）→ 失败。  
3. `.json`：`json.loads` 失败 → 失败。  
4. **除此之外一律通过**——包括 1～3 行的合法模块、`__init__.py`、单行 re-export 等。

**C. 文本文档族（md/txt…）**

1. 空或仅空白 → 失败。  
2. 整文件命中占位模板库（全等/仅换行）→ 失败。  
3. **不**用长度、**不**用「含 placeholder 单词且短」——避免误杀短 README；真要拦的是整篇只有那句套话。

**D. 占位模板库（精确匹配，V0）**

大小写不敏感、去首尾空白后与下列之一全等（允许末尾单个 `\n`）：

- `this is a placeholder.`  
- `this is a placeholder. run: python build.py to generate the actual …`（允许 `build.py` / `builder.py` 及其后至句末的常见尾句用前缀匹配：以 `this is a placeholder.` 开头且全文 `N≤320` 且无第二个段落）  
- `todo: generate`  
- `假文件` / `占位符` / `占位`

> 说明：对**源码/md**，宁可漏网也不用模糊「实质内容」比例；对**二进制冒充**，类型不符即足够。

#### 4.1.3 API

```python
def check_paths_integrity(
    root: Path, rel_paths: list[str],
) -> list[dict]:  # [{path, kind, detail}, ...]  空=通过
    ...
```

- 入口先 `ext → family`，再调族函数；禁止「先统一算实质内容再分支」。  
- **不**自动删假文件；**不**调 LLM。

### 4.2 返工 nudge 文案（固定模板）

注入 `role=user`（与现有 `repair_nudge` 并列或扩展）：

```
【交付物内容损坏/不合法—请返工】下列文件扩展名已匹配但内容校验失败，
禁止再次用 write_file 写入假后缀或明文占位：
- {path}: {detail}
修复要求（按类型）：
- .pptx → tool:slide_generator 生成真实 OOXML；
- .png/.svg 等图 → tool:arch_diagram 或写入合法二进制/SVG；
- .md/.txt 等文档 → 写入真实正文（非占位句）；
- 源码/.json → 写入可解析、非空的真实内容；
- .pdf/.docx/.zip → 写入合法格式文件，勿改扩展名冒充。
请修复后继续；收工前会再次做内容完整性校验。
```

计数：与存在性返工**共用** `_DELIVERY_REPAIR_MAX`（默认 3），避免「缺件 3 次 + 损坏 3 次」拖垮预算。  
实现：在 `_delivery_repair_counts[task_id]` 上统一累加；Stop 汇总里区分 `problems` 来源（`existence` vs `integrity`）仅影响 nudge 文案。

### 4.3 Worker 接入时序

修改点：`project_runtime/worker/llm_worker.py` 中交付 Stop 分支（提前收工路径）。

```
report = await self._delivery_stop_report(wp)   # 存在性
integrity = check_paths_integrity(scan_root, hit_paths)

if report.problems:
    # 既有存在性返工 / 软放行（ui 默认上屏）
    ...
elif integrity:
    used = self._delivery_repair_counts.get(tid, 0)
    if used < _DELIVERY_REPAIR_MAX:
        self._delivery_repair_counts[tid] = used + 1
        messages.append({integrity_nudge...})
        continue   # 再开工具轮
    self._raise_delivery_gap_soft(
        reason="CONTENT_INTEGRITY_SOFT",
        report=...,  # problems 来自 integrity
        extra={
            "ui_visibility": "audit_only",
            "integrity_failures": integrity,
        },
    )
else:
    # 双过 → 正常成功
```

`hit_paths`：与本次存在性检查同一文件枚举（任务目录；若 Stop 已 `scan_root=project` 则含分片目录下的假 pptx），避免收口令牌偏瘦导致漏检。

预算用尽路径（Grace 后 Stop）：完整性失败 **不再**开工具返工（已无工具预算）→ 直接 `CONTENT_INTEGRITY_SOFT` + `audit_only` 软放行。

### 4.4 delivery_gap 载荷

```json
{
  "soft_accepted": true,
  "reason": "CONTENT_INTEGRITY_SOFT",
  "ui_visibility": "audit_only",
  "problems": [
    "假/损坏 PPT：34/deliverables/solutions/解决方案介绍.pptx（非合法 OOXML）"
  ],
  "integrity_failures": [
    { "path": "34/deliverables/solutions/解决方案介绍.pptx",
      "kind": "pptx_not_ooxml",
      "detail": "not a zip / missing ppt/" }
  ],
  "repair_attempts": 3
}
```

Gate：沿用 SYS-138 `soft_accepted` → `PASS_WITH_GAP` → `ACCEPTED`。

### 4.6 架构边界

- Stable Kernel：不新增任务状态；仍 `ACCEPTED` + TaskRun。  
- 自动化模式：仅 FULL_AUTO / MANUAL。  
- 完整性属 Core 校验，非插件 DIRECT_STATE_MUTATE。  
- Resource Governor 正交。  
- **不**在本方案修复过载拆分令牌偏瘦（另案）；靠统一扫描根兜底漏检。
