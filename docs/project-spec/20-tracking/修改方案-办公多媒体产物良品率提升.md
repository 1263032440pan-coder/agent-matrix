# 修改方案：办公/多媒体产物良品率提升（对照开源智能体）

> 版本：2026-11-01（rev4：闭合落盘路径、受控后缀、shell 旁路与软放行终态；rev3 的产品边界不变）  
> 前置：V1.6 三件交付；`slide_generator` / `arch_diagram`；完整性静默软放行方案（假 pptx/png）；SYS-093～095 技能沙箱；`20-Worker-Runtime` 已有 Hermes Bot Mode 参照边界  
> 状态：**草案（待拍板）**  
> 问题：代码类产物尚可；`.docx` / 图片 / 表格 / `.pptx` 观感与可用性差；模型常绕过专用工具，用 `write_file`+`shell` 造占位文件。

---

## 〇、本项目定位与对照边界（先读）

本仓库是 **本地单用户桌面应用**：Microkernel + AOP/Extension Runtime；交付靠 **Project State / Task Graph / Gate / Proposal→Transaction**；自动化仅 **FULL_AUTO / MANUAL**。  
对照开源是为了偷 **机制**（写盘路由、反馈回路、专用 ACI），**不是**改成另一类「聊天 Bot / 开发者智能体应用」。

| 对照物形态 | 典型例子 | 与本项目关系 |
|--|--|--|
| **聊天/Bot 产品** | Hermes **Bot Mode**、Messaging Gateway（TG/Discord/…）、Grok Bot 类常驻对话助手 | **产品拓扑不同**：多 Bot 人设、网关会话、Bot↔Bot `message_agent`、远程常驻。本项目是 **项目任务图驱动的 Worker**，不是 Bot roster。规范里已写明：Hermes 人工勾选白名单对 FULL_AUTO 中途派生不适用（见 `20-Worker-Runtime` §派生闸）。 |
| **IDE/CLI 编程助手** | OpenCode、Aider、Claude Code 系 | **会话形态不同**：人对着仓库闲聊改码。我们可抄「write=文本 / 跑测回灌」，不抄其 UX 与权限模型当内核。 |
| **云沙箱 SWE 平台** | OpenHands 全量 Docker/远程 | **部署形态不同**：可远期 ADR 评估「任务执行后端」，不作为 Demo 办公良品前置，更不整平台搬迁。 |
| **办公专用 ACI** | OfficeCLI、DocuLane、docforge、powerpoint-skill | **机制最贴**：结构化生成 + 可选预览。以 Provider/插件接入，服从权限四档与 Stable Kernel。 |

**只参考、不照搬（机制白名单）**

- 可参考：拒 `write` 造二进制；生成后结构/预览反馈；Office 走专用工具或受控 MCP 桥；代码侧「写后轻量诊断 / 真跑测试」思想。  
- 不照搬：Bot Mode / 多平台网关 / 常驻 IM 助手；六后端云沙箱矩阵；完整 LSP 语言服务器集群；把 Core 改成 MCP-first 编排器；用「聊天会话质量」替代 Gate/清单对账。

## 一、现状回答（事实）

### 1.1 常见文件是怎么生成的？

| 类型 | 设计路径 | 实际常走路径 | 结果 |
|--|--|--|--|
| 源码 / md / json | `write_file` / `append_file` | 同左 | LLM 擅长文本 → **相对凑合** |
| 跑测 / 构建 | `test_runner` / `builder` / 白名单 `shell` | 有则用，模型也可能只写不跑 | **有能力但不强制** |
| PPT | **`slide_generator`**（md→python-pptx）或 skill `ppt-master` | 常被 `write_file` 假 `.pptx` + `build.py`+`shell` 替代 | **效果差 / 假文件** |
| 图（原型/流程） | **`arch_diagram`**（mermaid→mmdc→png，否则 `.mmd`） | 常写明文占位 `.png` 或自造脚本 | **差 / 假图** |
| docx / xlsx / 表格 | **无专用工具** | 只能 `write_file` 或 shell 调第三方 | **基本不可用** |

结论：**不全是**「写文件+命令行」。代码路径本就是文本工具；办公/媒体本应走专用 Provider，但约束弱，模型退化成写假后缀。

### 1.2 「沙箱」是不是工具调用？

两套概念，勿混；**开源项目也把二者拆开**：

| 名称 | 是什么 | 怎么进 |
|--|--|--|
| **Skill 安装沙箱**（SYS-093） | 四闸：AST / bwrap 冒烟 / 信任 / hash+venv | **安装 EXECUTION skill 时**，不是 Worker 每轮工具 |
| **Worker 执行面** | `shell` 白名单 + 工作区禁闭；`test_runner`/`builder` | **是工具调用**；Windows≈超时+净化 env |
| **对照：Hermes Terminal Backend** | local / Docker / SSH / Modal / Daytona / Vercel | **沙箱是「终端后端」配置**，file/terminal/`execute_code` 走同一环境；≠「某个叫 sandbox 的工具」 |
| **对照：OpenCode** | 自认 **不提供 OS 沙箱**；`permission` 只是 allow/ask/deny UX；真隔离靠外层容器 / Vercel Sandbox | 与我们「白名单 shell ≠ 隔离」同构 |
| **对照：OpenHands** | 推荐默认 Docker，bash/ipython 在容器内 | 任务级隔离最重的一档 |

因此：你看到的「沙箱有了」，多半是 **skill 安装隔离 + shell/test 受限执行**；模型写代码后**不会自动**进沙箱跑全套测试，除非主动调 `test_runner`/`shell`。这与 OpenCode「权限≠沙箱」、Hermes「后端可换但默认 local」一致——**良品率靠反馈回路，不只靠隔离**。

### 1.3 落盘与收工事实（阶段 A 的约束）

下面几条是现行代码和已拍板的完整性草案。后面的阶段按这个排，避免封死唯一写得进槽位的通道，或把终态改写成另一套。

| 事实 | 对方案的约束 |
|--|--|
| `write_file` / `append_file` 只 `write_text` UTF-8 | 写不出合法 OOXML/位图。拒写是让模型少空转，不是从它手里收回一种真二进制能力 |
| `slide_generator`：任务工作区存在时，输出钉在工作区根；文件名中的 `/` `\` 换成 `_` | 写不进清单槽位 `deliverables/{slot}/…`。今天能把字节写进该相对路径的，是 `write_file` 和 shell 脚本 |
| `arch_diagram`：没有 `mmdc` 时 `ok=true`，落 `.mmd`，不产 png | `.mmd` 满足不了扩展名为 `.png` 的清单项 |
| `shell`：`python build.py` 在路径 token 规则内允许；`echo` 参数不限，执行走 `shell=True`，`>` 不在禁用模式里 | 问题陈述里的旁路是通的。安装闸放过的 skill 脚本另有入口 |
| 派生结果 ⊆ 环节模板插件上限；安全增量集里没有未来的 office 工具。编码模板有 `shell`、无 `slide_generator`；分析/设计模板有 slide/arch、无 `shell` | 只改 prompt 变不出上限里没有的工具 |
| 完整性草案已拍板 | nudge 用尽，或 Grace 之后已经没有工具预算 → `CONTENT_INTEGRITY_SOFT` + `audit_only` + Gate `PASS_WITH_GAP` → **仍 ACCEPTED**。与缺件共用返工次数上限。节点上不展示这类缺口 |

## 二、为何代码尚可、办公媒体很差

1. **模态不匹配**：LLM 原生输出文本；OOXML/位图是结构化二进制，用 `write_file` 几乎必然假货。  
2. **专用工具弱且可绕过**：`slide_generator` 仅「md→简易版式」；无 docx/xlsx；无「渲染预览→返工」闭环。  
3. **Stop 只验存在性**（完整性方案补结构，仍非观感）。  
4. **激励错位**：占位文件也能过 Gate。完整性草案落地后，限次用尽仍是 ACCEPTED（静默软放行），所以压力来自少产出坏文件，不来自把终态改成失败。  
5. **对照缺口**：开源头部在「写后反馈」上明显更重——Hermes **write 后喂 LSP 诊断**；OpenCode **`read` 可把 PNG/PDF 像素送回模型**；办公则走 **MCP/Skill/CLI**，而不是 `write` 造二进制。

## 三、开源智能体对照（扩面）

### 3.1 总表

| 项目 | 产物怎么出 | 沙箱 / 执行面 | 办公·图·表 | 可抄的一招 |
|--|--|--|--|--|
| **OpenCode**（anomalyco） | `write`/`edit`/`patch` 文本；`shell`；Code Mode `execute` 链工具 | **无内置 OS 沙箱**；permission allow/ask/deny；外挂容器/Vercel | 内置 `experimental_image_generate`；Office 靠 **Skill + MCP**（DocuLane / docforge 等） | ① `write` 只服务文本；② **`read` 可多模态回传图/PDF**；③ Office **外挂 MCP，不扩 write** |
| **Hermes（工具/执行面）** | `write_file`/`patch` + `terminal`/`execute_code` | 可插拔终端后端（local…云） | `vision_analyze` / `image_generate`；可读 docx/xlsx | **仅机制**：写后诊断思想、视觉回看、沙箱≠工具名。**不抄** Bot Mode / Gateway（见 §〇） |
| **Hermes Bot / Grok Bot 类** | 常驻对话、多 Bot、IM 网关 | 网关进程 + 远程环境 | 附件随聊发出 | **产品形态对照用**：证明「助手应用 ≠ 本项目」；本方案**零采纳其拓扑** |
| **OpenHands** | bash + ipython（CodeAct） | 默认 Docker 等隔离 | 复杂能力偏 Skill | 代码「真跑」思想；不搬整平台 |
| **Goose**（Block） | MCP-first；Code Mode | 扩展可容器化 | Office = MCP extension | 办公放扩展层；不把 Core 改成 MCP 编排器 |
| **Aider** | 编辑格式 + git | 基本无沙箱 | 不覆盖 Office | lint/test 回灌思想 |
| **OfficeCLI / DocuLane / docforge / ppt skill** | 结构化 create/edit/info；部分渲染预览 | 本地引擎/子进程 | **专攻** OOXML | 与本项目 ACI 最贴；经 Provider/插件接入 |

### 3.2 可迁移共性（机制层，不是产品层）

```
代码良品 ≈ 文本编辑 ACI +（跑测 / 轻量诊断）反馈      → 落入 Worker 工具 + Stop/Gate
办公良品 ≈ 专用编辑 ACI +（结构校验 / 规则预览）反馈  → 落入 slide/arch/docx Provider + 完整性
图片良品 ≈ 专用管线（mermaid/生成器）+ 可选回看         → 落入 arch_diagram，不默认扩散模型
沙箱      ≈ 执行边界（skill 闸 / shell 白名单）          → 不升格为「Bot 云主机矩阵」
```

头部差距在 **反馈回路 + Office 专用面**，不在「谁更像聊天 Bot」或「谁的 shell 更炫」。  
**OpenCode / Hermes 工具层**都不把「`write` 吐 pptx 字节」当正路。本项目 `write_file` 已是 UTF-8 文本；某个后缀何时禁止它写，取决于专用工具是否已经能写进清单相对路径（见 §1.3、阶段 A0/A1）。

### 3.3 对我们现状的定位（在本架构内）

| 维度 | 我们（应保持的骨架） | 缺口（本方案要补） |
|--|--|--|
| 编排 | Task Graph + Gate + FULL_AUTO/MANUAL；非 Bot 会话 | 不改拓扑 |
| 代码写盘 | `write_file` + 可选 `test_runner` | 可选：收工测门、写后轻量诊断（**非**完整 LSP 集群） |
| PPT/图 | 已有 `slide_generator` / `arch_diagram` | 先能写进清单路径，再按后缀封旁路；版式另升级 |
| docx/xlsx | 无 | 新 Provider 或受控插件桥（ADR） |
| 视觉回环 | 基本无 | V0 规则预览即可；多模态为可选增强 |
| 沙箱 | skill bwrap + shell 白名单 | 够用则维持；云后端仅远期 ADR，**非本方案主线** |

## 四、目标与原则

**目标（分开看）**

- 阶段 A 量 **可打开率** 和 **假后缀率**：真实可打开的 pptx/png 变多，明文占位变少。观感不在 A 的验收里。  
- 观感靠阶段 B 的版式和阶段 C 的规则预览。页数、审美仍不进 Core 硬闸。  
- 代码测试门、写后诊断是可选增强，另走 CR，**不是**办公良品的前置。  
- `CONTENT_INTEGRITY_SOFT`：A2 上线后这个 reason 才开始记账，占比会先出现。下降只作为 A0/A1/B 生效之后的结果，不作为 A2 当天的验收。

**原则（对齐 AGENTS.md）**

- 专用工具 = Core/插件 Provider 或 **受控 MCP 桥**；经工具循环；**禁止** DIRECT_STATE_MUTATE。  
- **受控后缀表**分批扩大。某个后缀进入表的前提：已有合法生产者，且该生产者能覆盖清单相对路径。尚无生产者的后缀不进表。  
- 合法生产者只有两类：专用 Provider，以及安装闸放过的 skill 脚本。任意 `build.py`、`echo` 重定向不是合法生产者。  
- 本方案**不改**完整性草案的终态：限次之后仍软放行 ACCEPTED。  
- 新 Hook、测试硬门走 CR。Resource Governor 与自动化模式正交，不混。  
- 新工具要同时进入「安全增量集或环节模板上限」和契约关键词表。只改 prompt 不算接入。

## 五、改进方案（分阶段）

### 阶段 A — 先对齐路径，再按后缀封写 ★优先

阶段 A 提升的是可打开率。版式观感在阶段 B。

#### A0 清单相对路径（拒写之前）

1. `slide_generator` 的文件名改为相对任务工作区的路径：允许子目录，拒绝 `..`；不再把 `/` `\` 换成 `_`；需要时创建父目录；返回这个相对路径。  
2. `arch_diagram` 同样接受 png 的清单相对路径。  
3. 没有 `mmdc` 时：`ok=false`，`error_code=RENDERER_UNAVAILABLE`。不写占位 png，也不把 `.mmd` 当成该 png 槽位已交付。只有清单扩展名就是 `.mmd`，或调用方显式 `format=mmd` 时，才落 `.mmd` 并算成功。  
4. skill `ppt-master` 仍是 pptx 的合法生产者，但必须写到清单相对路径。写到别处，该项仍算未交付。

#### A1 `write_file` / `append_file` 只拒绝受控表

- 受控表初值：`.pptx`、`.png`。**A0 完成之后**才启用。错误码 `BINARY_SUFFIX_DENIED`，hint 带工具名，并要求路径等于清单相对路径。  
- `.docx` / `.xlsx` / `.pdf` / `.jpg` 等先不进表：没有能写该后缀的生产者。hint 写明「尚无专用工具，禁止明文占位」，不要指向还不存在的工具。这些后缀继续交给完整性 nudge。  
- `.svg` 保持文本路径（完整性草案已单列矢量族）。

#### A1b shell 旁路（与 A1 同一批，跟同一张表）

- 重定向（`>` / `>>`）的目标若落在完整性草案的二进制族（pptx/docx/xlsx/png/jpg/gif/webp/bmp/pdf/zip）→ 拒绝执行。`echo` 只能写出明文，从来不是合法生产者。这张「重定向拒绝表」可以比受控表更宽，因为它不关掉 python 写 docx 的过渡通道。  
- 非 skill 白名单的 `python` / `python3`：执行前记录**受控后缀**文件摘要，执行后若这些文件被新建或改写，**还原**并返回 `BINARY_WRITE_ESCAPE`，hint 指向专用工具。只还原受控后缀，不动脚本同时改过的源码。  
- skill 白名单脚本不还原。产物仍要落在清单路径上，并走完整性。  
- `.docx` / `.xlsx` 在进入受控表之前，不还原 python 对它们的写入。过渡期这是唯一能写出合法 OOXML 的通道。B2 的生产者能写清单路径、并进入环节上限之后，再把这两个后缀加入受控表，同时关闭这条过渡通道。

#### A2 完整性 nudge（终态沿用已拍板草案）

- 落地完整性草案，不把终态改成失败或不 ACCEPTED。  
- 验收：明文 `placeholder.pptx` 会进入完整性 nudge，不能在没 nudge 的情况下当成功收工。限次用尽，或 Grace 后已经没有工具预算：仍然 `CONTENT_INTEGRITY_SOFT` + `audit_only` + **ACCEPTED**（与该草案 T5/T6/T9 一致）。  
- 同一实施里改该草案 §4.2 的 nudge 文案，不另立终态：  
  - `.pptx` → `slide_generator` 或白名单 skill，输出路径等于清单相对路径。  
  - `.png` → `arch_diagram` 写该相对路径；没有 `mmdc` 就让工具失败，不要再写占位 png。  
  - 已在受控表内的后缀 → 禁止 `write_file` 和非 skill 脚本再写。  
  - 尚无生产者的 docx 等 → 禁止明文占位；过渡期允许脚本写出能过魔数的文件。  
- nudge 与缺件共用 `_DELIVERY_REPAIR_MAX`。A0 没做时，模型即使用 `slide_generator` 也覆盖不了槽位，次数会耗在同一条死路上。因此检出可以先做，**拒写 `.pptx` 必须排在 A0 之后**。

#### A3 prompt / derive

- 只点名该环节上限里已经有的工具。分析、设计、交付模板里已有 `slide_generator` 的，prompt 要求用它，并带上清单相对路径。  
- 编码模板没有 `slide_generator`：prompt 里不得要求调用它。开发环节的契约若含 pptx，要改的是该模板上限（单独变更）。  
- 新 office 工具在 B2 进入上限之前，不写进 prompt。

**阶段 A 验收**

1. A0 之后，`slide_generator` 能把文件写到 `deliverables/.../名称.pptx`，清单 match 打在这个路径上。  
2. A1 之后，`write_file` 写 `.pptx` / `.png` 得到 `BINARY_SUFFIX_DENIED`；写 `.docx` 仍走原路径，直到 B2。  
3. 非 skill 的 `python build.py` 若改写受控后缀，变更被还原。  
4. 明文假 pptx：Stop nudge；用尽后仍 ACCEPTED + `audit_only`。  
5. 没有 `mmdc` 时，`arch_diagram` 对 png 槽返回失败；工作区不出现占位 png，也不把 `.mmd` 报成该槽已完成。

### 阶段 B — 版式与 Office 生产者

| 工具 | 升级方向 | 说明 |
|--|--|--|
| `slide_generator` | 提纲 JSON/分镜；主题与页类型；返回页数/空页元数据 | 路径已在 A0。观感从这里开始 |
| `arch_diagram` | 渲染质量；失败原因写清 | 成功条件已在 A0 定死。`.mmd` 不再充当 png 槽位的交付 |
| **新增** `docx_generator` / `sheet_generator` | 自研 python-docx/openpyxl，**或** ADR 后嵌入 DocuLane/OfficeCLI/docforge | 三件一起做：Provider、`SAFE_INCREMENT_PLUGINS` + 契约关键词、需要该产物的环节模板上限（设计/交付）。三件齐，且能写清单相对路径之后，才把 `.docx` / `.xlsx` 列入受控表 |
| 可选 **MCP 桥**（插件） | 不把 30+ Office 工具塞进 Core | 权限保持 READ_ONLY / ENRICH / VALIDATE / CONTROL。工具名同样要进上限才调得到 |

### 阶段 C — 结构回环（工具返回值，不是常驻 vision）

1. 不依赖外部渲染器的检查先做：用 python-pptx / 解包读页数、空页标记，结果写进 tool result。  
2. 本机有渲染器（LibreOffice 或等价物）时，再渲染首页/关键页为 PNG 或 HTML。没有渲染器就跳过预览并注明，**不把已经通过完整性的文件判失败**。  
3. V0 返工语义 = 用**同一清单相对路径整篇重生成**。本阶段没有 edit/patch。  
4. V1（可选）：预览图多模态回看；费用与隐私另议。  
5. 对真实 docx/xlsx 抽结构摘要，只用来决定要不要整篇重生成。`read_file` 今天按 UTF-8 读，不能当 docx 编辑底稿。出现 edit 工具之后，才能把文案改成局部修改。

### 阶段 D — 代码真跑与写后反馈（另 CR，非办公前置）

1. 硬门若做：契约标明要测试的节点，必须 `test_runner` 成功一次。模型当场「声明跳过」不算通过。没挂测试的节点不加这道门。另 CR。  
2. 写后语法/轻量 lint 是新的后置 Hook，和完整 LSP 一样要 CR。无 CR 时不挂上 Write Provider。只回灌本次写入引入的错误。不上多语言 LSP 守护进程。  
3. 任务级 Docker/云后端：**另案 ADR**。不是办公良品前置，也不是 Bot 网关配套。

### 阶段 E — 度量与收口

- **可打开率、假后缀率、专用工具写入清单路径的占比**（看 A/B）。  
- `CONTENT_INTEGRITY_SOFT` 次数：A2 之后才有分母；先升是记账效应；生产者生效之后的下降才是目标。  
- 观感不设 Core 硬指标。预览返工轮次、`test_runner` 占比只在 C/D 打开后统计。  
- 项目收口：沿用完整性草案，V0 不因完整性阻断收口；失败记录可进补建候选。

## 八、风险与边界

- 没有 `mmdc` 时，png 槽会走存在性失败再软放行。这是预期：不产假 png。要有 png 良品，环境里需要渲染器。  
- 过渡期 docx/xlsx 仍可能由 python 脚本生成，质量不在阶段 A 的验收里。  
- 预览渲染器缺失时跳过预览，不把已通过完整性的文件判失败。  
- 拒写 hint 必须带清单相对路径，否则模型仍会写到工作区根。  
- shell 还原只针对受控后缀，避免误伤同一次命令改过的源码。  
- 外挂 Office MCP/CLI：许可证、体积、Windows → **必须 ADR**；接入须服从 READ_ONLY / ENRICH / VALIDATE / CONTROL。  
- 视觉多模态：费用与隐私 → V0 不做。  
- 页数≥6 等审美不进 Core 硬闸；Core 保 **真实 + 可打开 + 基本结构**。  
- 对照文案若写成「做成 Hermes/Grok Bot」一律视为越界——本项目交付面是 **桌面项目工作台 + 产物清单**，不是 IM Bot。
