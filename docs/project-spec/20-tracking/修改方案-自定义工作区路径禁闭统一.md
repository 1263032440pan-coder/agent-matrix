# 修改方案：自定义工作区路径禁闭统一

> 版本：2026-11-06  
> 前置：`workspace_path` / `resolve_project_workspace` / `resolve_task_workspace`（V1.6）；办公工具 `__ws_root` 注入；`office_inspect` / 文件工具读禁闭  
> 触发：自定义工作区项目（如 Desktop/`测试17`）上 `image_raster` 写 PNG 成功，随后 `office_inspect` 同相对路径报 `OUT_OF_SCOPE`；Agent 误判「文件未落盘」  
> 状态：**已落地**（2026-11-06：S0～S3 + 收尾 todo/code_search/git/builder/test_runner + test_workspace_scope）  
> 拍板约束：不把所有工具收成同一把尺子；统一「工作区怎么算」，保留写窄 / 读宽分层。

---

## 一、问题

1. **写成功、检失败**：`image_raster` 将 `deliverables/*.png` 写入  
   `{workspace}/.agent-matrix/tasks/{tid}/...`，`office_inspect` 对同一相对路径返回 `OUT_OF_SCOPE`。  
2. **硬编码旧根**：读侧多处仍用 `_data_tasks_root()`（`cwd/data/tasks`）作允许范围；自定义 `workspace_path` 下任务根不在该树内 → 合法路径被拒。  
3. **标准不一致**：写工具按 `__ws_root` 禁闭；部分读/检工具按 `data/tasks` 禁闭；同一次工具循环内语义分裂。  
4. **连带风险**：`read_file` / `list_dir` / `shell`（`resolve_workspace_path`）在自定义工作区下同样可能越界误拒或 cwd 锁错根。

根因不是相对路径写错，而是 **读禁闭未跟随「项目工作区解析」演进**。

---

## 二、拍板结论

| # | 结论 |
|--|--|
| 1 | **不**要求全体工具同一允许范围；保留分层：写窄、读宽、Skill 独立根 |
| 2 | **必须统一**「允许根」的解析来源：一律由 `workspace_path` → project/task workspace 推导，禁止业务工具私自硬编码 `data/tasks` 当唯一根 |
| 3 | **写范围** = 本任务 `__ws_root`（`resolve_task_workspace`） |
| 4 | **读范围** = 本项目 **project workspace**（`resolve_project_workspace`）；默认布局下等价于可覆盖同仓任务树的父根（历史 `data/tasks` 行为兼容） |
| 5 | `office_inspect` 属**只读检视**，走读范围，不得再 `_within(..., _data_tasks_root())` |
| 6 | Skill 工具（`skills_list` / `skill_view`）继续锁 Skill 安装根；本方案不改 |
| 7 | 禁止借机放开到盘符任意路径；越出 project workspace 仍 `OUT_OF_SCOPE` |

---

## 三、名词

| 名词 | 含义 |
|--|--|
| **project workspace** | `resolve_project_workspace(pid, workspace_path)`：用户指定绝对目录，或回落 `data/tasks/{pid}` |
| **task workspace / `__ws_root`** | `resolve_task_workspace(...)`：默认 `data/tasks/{pid}/{tid}`；自定义则为 `{project}/.agent-matrix/tasks/{tid}` |
| **写允许根** | 仅 task workspace |
| **读允许根** | project workspace（含其下 `.agent-matrix/tasks/*` 与用户仓库树） |
| **旧读根** | `_data_tasks_root()` → `Path("data/tasks").resolve()`，与 cwd 绑定，**不感知** `workspace_path` |

## 四、现状对照

| 工具 / 入口 | 当前允许检查 | 自定义工作区表现 |
|--|--|--|
| `write_file` / `append_file` | `_within(resolved, ws_root)` | 正确 |
| `office_*` / `image_raster`（`resolve_output_path`） | `_within(resolved, ws_root)` | 正确 |
| `office_inspect` | 有 ws 时仍 `_within(..., _data_tasks_root())` | **误拒**（本案触发点） |
| `read_file` / `list_dir`（`_FileToolBase._target` 读支） | `_within(..., _data_tasks_root())` | **误拒**同根外任务/仓库文件 |
| `shell` / 部分 coding 工具经 `resolve_workspace_path` | 强制落在 `data/tasks` | cwd / scope **可能锁错** |
| Skill 工具 | Skill 根 | 不受影响（本方案不动） |

实测（项目 17，`workspace_path=C:\Users\...\Desktop\测试17`）：

- 落盘：`...\测试17\.agent-matrix\tasks\223\deliverables\prototype\prototype.png`（存在）  
- `office_inspect` error：`路径越界: deliverables/prototype/prototype.png`（`OUT_OF_SCOPE`）

## 五、方案分块

### 5.1 统一「读/写允许根」API（单一真相）

在 `project_runtime/workspace.py`（或 `worker/tools.py` 薄封装，避免循环依赖）增加纯函数，例如：

```text
write_allow_root(task_ws: Path) -> Path
  # 即 task_ws 本身

read_allow_root(*, project_ws: Path | None, task_ws: Path | None) -> Path
  # 优先 project_ws；缺省时从 task_ws 推导：
  #   - 若 path 形如 .../.agent-matrix/tasks/{tid} → parents[2]
  #   - 若 path 落在 data/tasks/{pid}/{tid} → data/tasks（兼容旧测例跨任务读）
  #   - 否则 → task_ws（最窄兜底）
```

Worker 注入（`llm_worker` 工具 payload）：

| 字段 | 含义 |
|--|--|
| `__ws_root` | 已有，task workspace（写禁闭） |
| `__project_ws_root` | **新增**，project workspace（读禁闭） |

有 `__project_ws_root` 时读检查一律用它；无则走 `read_allow_root` 从 `__ws_root` 推导（兼容旧调用/单测）。

### 5.2 修正 `office_inspect`（P0）

```695:698:project_runtime/office/providers.py
# 现状（错误）
resolved = resolve_task_path(path, ws)
if not _within(resolved, _data_tasks_root()):
    return tool_error("OUT_OF_SCOPE", ...)
```

改为：

1. `resolved = resolve_task_path(path, ws)`（ws 仍为 task root，保证相对路径语义与写工具一致）  
2. `allowed = read_allow_root(project_ws=payload.__project_ws_root, task_ws=ws)`  
3. `_within(resolved, allowed)`；失败文案写明「只允许本项目工作区内」，并带 `allowed` 展示路径  

无 ws 时：回落 `resolve_workspace_path` **或**（更干净）要求 inspect 必须带 `__ws_root`（与 `needs_workspace_root=True` 一致）；Demo V0 可保留回落但标注为遗留。

### 5.3 修正文件工具读支（P0，与 inspect 同语义）

`_FileToolBase._target(..., write=False)`：

```text
allowed = ws_root if write else read_allow_root(project_ws=..., task_ws=ws_root)
```

替换 `allowed = _data_tasks_root()`。  
写支不变。hint 文案：「其他任务目录只读」→「本项目工作区内其他任务目录只读」。

### 5.4 `shell` / `resolve_workspace_path` 调用点（P1）

- `ShellProvider`：cwd 应硬锁 **`__ws_root`（task）**，不得再把 workspace 参数塞进 `resolve_workspace_path`（该函数只认 `data/tasks`）。  
- 审计 `coding_tools` / `todo` / `code_search` 等对 `resolve_workspace_path` 的使用：凡任务执行路径，改为 task/project 根 API。  
- `_data_tasks_root` / `resolve_workspace_path` 可保留给「无自定义工作区的遗留单测与无 `__ws_root` 的兜底」，但 **禁止**新业务逻辑直接依赖。

### 5.5 错误码与提示（不变码、改文案）

- 仍用 `OUT_OF_SCOPE`（审计统计兼容）。  
- hint 必须区分：  
  - 写出界 → 「请使用相对本任务工作区的路径」  
  - 读出界 → 「只允许本项目工作区内；自定义工作区 ≠ data/tasks」

## 六、非目标

- 不引入第三种自动化模式；不改 Gate / Proposal 主路径。  
- 不放开 `DIRECT_STATE_MUTATE`；路径禁闭仍是插件侧 ENRICH/只读约束。  
- 不把 Skill 目录并入 project workspace。  
- 不做跨项目任意读（自定义工作区项目不得读到别的 Desktop 目录）。  
- 不在本切片重构全部 office 后端；OfficeCLI `assert_within(path, ws)` 已按任务/传入根检查的保持。

## 八、测试要点

1. **自定义工作区 round-trip**：临时目录作 `workspace_path` → task_ws 下 `image_raster`（或写字节 fixture）→ `office_inspect` 同相对 path → `ok`。  
2. **默认布局回归**：无 `workspace_path` 时，跨任务 `read_file("data/tasks/{pid}/{other}/x")` 仍允许（兼容 `test_read_upstream_task_allowed`）。  
3. **写出界**：写到 task_ws 外 → `OUT_OF_SCOPE`。  
4. **读出界**：`C:/Windows/...` 或邻接无关目录 → `OUT_OF_SCOPE`。  
5. **推导兜底**：仅有 `__ws_root`、无 `__project_ws_root` 时，`.agent-matrix/tasks/{tid}` 能推导出 project 根。  
6. **shell cwd**（S3）：自定义 ws 下 cwd == task_ws。

## 九、风险与回滚

| 风险 | 缓解 |
|--|--|
| 读范围若误设为「整盘 / 用户主目录」 | API 只接受注入的 project_ws；推导失败则收窄到 task_ws |
| 旧测例假定读根=`data/tasks` | S0 明确默认布局分支；必要时测例改为注入 `__project_ws_root` |
| 只修 inspect 不修 read_file → 症状转移 | S1/S2 同语义一次对齐 |
| cwd 进程不一致导致 `_data_tasks_root()` 漂移 | 长期以绝对 `__project_ws_root` 为准，减少对 cwd 的依赖 |

回滚：恢复 `office_inspect` / `_target` 读支对 `_data_tasks_root()` 的检查；自定义工作区项目将再次出现本案故障。
