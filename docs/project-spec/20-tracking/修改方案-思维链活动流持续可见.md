# 修改方案：思维链面板「全程活动流」持续可见

> 日期：2026-10-31  
> 状态：已实现（2026-10-31）  
> 定案：面板标题「运行动态」；Worker content 前端仅保留近 50 行。  
> 目标：静默阶段（工具 / 等 token / 仅 content / Gate·校验）在工作台「运行动态」区仍有可读输出。

---

## 1. 问题

`ThinkingPanel` 只消费 `LLM_THINKING_CHUNK`（及规划侧 `LLM_ANSWER_CHUNK`）。  
下列阶段**有活、无链**：

| 静默段 | 实际在做 | 现有信号（未进思维链） |
|--------|----------|------------------------|
| 工具轮 | write_file / search / slide… | `LLM_TOOL_CALL` / `LLM_TOOL_RESULT` |
| 等下一 token | 网关慢推流 | 无（Worker 无 idle 切断） |
| 只写 content | 正文流式、无 reasoning | `LLM_ANSWER_CHUNK`（Worker **未** emit） |
| Gate / 校验 / 交付硬闸 | 脚本、match、stop | `DELIVERY_VALIDATOR_*` / Gate 事件等 |
| 规划非抽取阶段 | manifest / gap / assign | 多数无 CoT |

---

## 2. 方案对比

| | A. 同面板活动流（推荐） | B. 概览 Runtime Events 迁回 | C. 仅前端合成 |
|--|------------------------|-----------------------------|---------------|
| 做法 | 扩展 `/agent-thinking` + 后端补 emit；ThinkingPanel 分类型渲染 | 恢复 Events 列表 | 前端再轮询 dashboard events 拼进思维链 |
| 优点 | 用户盯一块即可；轻量 API；与现 1s 轮询一致 | 改动小 | 不改枚举 |
| 缺点 | 要改 emit + UI 样式 | 与「概览改清单」冲突；工作台仍看不见 | 双轮询抢锁；类型不全 |
| 推荐 | **是** | 否 | 否 |

**推荐 A**：把「思维链面板」升级为 **运行活动流（Activity + CoT）**，概念上仍叫思维链区，行类型区分。

---

## 3. 推荐设计

### 3.1 事件模型

新增（或复用并规范化）事件类型，一律走 `EventEngine.record` 短事务：

| `event_type` | 何时 emit | `message` 示例 |
|--------------|-----------|----------------|
| `LLM_THINKING_CHUNK` | 既有 reasoning | （原文） |
| `LLM_ANSWER_CHUNK` | **Worker 也改为**对流式 `content` 缓冲 emit（与规划对齐） | 正文片段 |
| `LLM_TOOL_CALL` | 已有；纳入 thinking API | `调用工具 write_file path=…` |
| `LLM_TOOL_RESULT` | 已有则纳入；否则补 | `工具完成 write_file ok=true 耗时 1.2s` |
| `AGENT_ACTIVITY`（新） | 无细事件时的阶段心跳 | 见下表 |

**`AGENT_ACTIVITY` 阶段文案（中文固定模板）**

| phase | 文案 |
|-------|------|
| `llm_wait` | `等待模型输出…`（流式开始后、首 chunk 前；或 chunk 间隔 >3s 再发一条，防刷屏） |
| `gate` | `质量关卡评估中…` |
| `delivery_stop` | `交付硬闸校验中…` |
| `validator` | `运行交付校验脚本…` |
| `plan_phase` | `规划阶段：{name}…`（manifest / gap / assign 等） |
| `skill_select` | `选择技能中…` |
| `research` | `执行研究检索…` |

节流：同类 `AGENT_ACTIVITY` **≥3s** 才允许再写一条；工具 call/result **每工具一次**不节流。

### 3.2 API

`GET /api/projects/{id}/agent-thinking` 事件类型扩展为：

```
LLM_THINKING_CHUNK | LLM_ANSWER_CHUNK |
LLM_TOOL_CALL | LLM_TOOL_RESULT | AGENT_ACTIVITY
```

响应字段增加：

```ts
{
  event_id, task_id, timestamp,
  kind: "thinking" | "answer" | "tool" | "activity",
  text: string,           // 展示文案
  agent_instance_id?, agent_name?,
  payload?: object        // 可选：tool name、ok、path
}
```

`kind` 由服务端从 `event_type` 映射，前端不解析枚举表。

### 3.3 UI（ThinkingPanel）

- 标题可仍为「思维链」，副标题：`思考 / 工具 / 活动`。
- 行样式：
  - `thinking`：现有弱化左边线
  - `answer`：稍强调（正文）
  - `tool`：等宽小字 + 前缀 `⚙`
  - `activity`： muted + 前缀 `…` / `⏳`
- 同一滚动区、时间序追加；任务切换仍清空（现逻辑保留）。
- `phaseHint`（规划中）保留。

### 3.4 后端埋点位置（最小集）

| 位置 | 动作 |
|------|------|
| `llm_worker._stream_round` | content → `_emit_cot(..., "answer")`；首 chunk 前 / 空闲 >3s → `AGENT_ACTIVITY llm_wait` |
| `llm_worker` 工具前后 | 已有 TOOL_*；确保 message 可读中文摘要 |
| `llm_worker` delivery stop / validator | `AGENT_ACTIVITY` |
| `execution/service` Gate 前后 | `AGENT_ACTIVITY gate` |
| `projects.py` `/plan` 各 phase 入口 | `AGENT_ACTIVITY plan_phase` |
| `llm_extractor` | 已有 thinking/answer，可加「抽取流式开始」activity 一条 |

### 3.5 非目标

- 不恢复概览 Runtime Events 大块。
- 不把完整工具 stdout / 整份脚本日志灌进面板（只摘要）。
- 不改 Stable Kernel 状态机；仅 Event 只读流。

### 3.6 实现切片

1. **P0**：API 扩类型 + ThinkingPanel `kind` 渲染；Worker content→ANSWER_CHUNK；TOOL_* 进流  
2. **P1**：`AGENT_ACTIVITY` + llm_wait 节流；Gate / delivery_stop / plan_phase  
3. **P2**：文案打磨、单测（emit 断言 + 面板 kind 样式）

### 3.7 风险

- 事件量↑ → 仍 1s 增量拉取 + 服务端 limit；activity 节流。  
- SQLite：继续短事务 `record`，与现 CoT 同范式。
