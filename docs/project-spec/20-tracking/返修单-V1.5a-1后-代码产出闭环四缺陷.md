# 返修单：V1.5a-1 集成实测暴露四缺陷修复（代码产出闭环）

> 对象：任务5 实测诊断出的四个断点（2026-10-22 用户问询确认）
> 依据：事件流 740 条/DB/磁盘三面实证（见各条证据）
> 原则不变：行为在 skill 层，代码只做机制——本次全部是机制侧修复

---

## 缺陷 1（P0·安全）：file_rw 工作区禁闭粒度错——任务可写全库

**证据**：模型把 `login_api/`（4 个代码文件）写到 `data/tasks/` 根；harvest 只扫任务工作区 `data/tasks/{pid}/{tid}/`，全没登记。FileRwProvider docstring 自己写着"限定 data/tasks/{project}/{task}/"，实现却是整个 `data/tasks/`。

**根因**：`_resolve()` 禁闭根取 `data/tasks`（项目级以上），且 Provider 无任务上下文——它根本不知道自己正服务哪个任务。

**修复**：任务级禁闭，写路径锁进 `data/tasks/{pid}/{tid}/`。

1. `WorkPackage` 加 `workspace_root: str | None = None`（dataclass 字段，service.py 构造时传 `data/tasks/{project_id}/{task_id}`——与 ArtifactManager 同源同参数）
2. `_run_tool_plugin` 分发 `tool:file_rw` 的 write action 前注入上下文：payload 附 `__ws_root`（下划线前缀=内部参数，schema 不暴露）
3. `FileRwProvider.invoke` write 分支：有 `__ws_root` → resolved 必须落在其内，越界返回可理解错误文案（"请写入本任务工作区 {root} 内，路径如 src/main.py"——指引而非拒绝）；无 `__ws_root`（测试/独立调用）→ 维持 `data/tasks` 原语义（向后兼容）
4. read/list 维持 `data/tasks` 全域（读上游产物是合法需求）

**不引入新 Extension Point**：`__ws_root` 走既有 invoke payload 通道，Provider 签名零变更。

## 缺陷 2（P0·数据）：planner 归一 code_stage 时漏补 stage_outputs

**证据**：项目1 任务 5-8 `code_stage=true` 但 `stage_outputs=[]`；skill 1.1.0 的四件套只在骨架路径透传，用户方法路径（真流程文档——主场景）拿不到。

**根因**：我上轮补强只写了布尔标记，漏了修订单 §三B"三行最小条款"的代码侧形态。

**修复**：`planner.py::_create_task_for_workstream`——`code_stage_flag=True` 且 `stage_outputs` 为空时，补默认四件套 `[入口文件, 功能模块, 测试文件, README]`（与 skill 1.1.0 开发实现阶段 outputs 完全一致——代码兜底与 skill 声明同构，非新行为）。skill 透传的优先（非空不覆盖）。

## 缺陷 3（P1·漏项）：Gate 无代码交付检查——"光说不练"照收 PASS

**证据**：任务5 产物 287 字符思考开场白，工作区零代码文件，`FileValidator` 只查"artifact 文件存在+sha256 对"，PASS 放行。

**根因**：设计单第②件明确列了"Gate 检查（entry+README 存在）"，实施清单序 6 我漏了。

**修复**：`gate.py` 加第四个 `CodeDeliveryValidator`：

1. 触发条件：task 的 playbook_ref 含 `code_stage: true`（读 Task.playbook_ref JSON，与 service 同款解析）
2. 检查（对工作区 `data/tasks/{pid}/{tid}/`，不是 artifact 表——模型可能没登记就收工）：
   - 至少 1 个代码文件（.py/.js/.ts/.html/.css 其一）
   - README 存在（README.md/readme.md 不分大小写）
3. 结果：缺 → `FAIL`（"代码任务未交付代码文件/README，工作区仅 {n} 个非代码文件"）→ 既有 REWORK 链（Gate FAIL → REWORK → 重提交）
4. 非 code_stage 任务零影响（validator 直接 PASS）
5. **不跑测试**——测试跑不跑通是硬门的事（附录草案，等用户拍板），本 validator 只查"交付物存在性"，与 FileValidator 同级同语义（记账不是行为）

## 缺陷 4（P2·体验）：skill 触达窗口 2000 字偏小，纪律段+开发阶段细则可能被裁

**证据**：1.1.0 纪律总则实测位置 1399 字符（窗口内），但分阶段细则里"开发实现"的执行纪律（第 6 阶段，正文 ~4000 字符处）在窗口外——模型只看到总则"要写测试"，看不到"怎么组织多文件"。

**修复**（保守渐进）：`llm_worker.py:324` 截取 `skill_body[:2000]` → `[:3000]`，且 code_stage 任务追加阶段细则段（定位"开发实现"标题到下一阶段标题之间，追加在纪律总则后，上限 1500 字符）。

- 不改 skill（行为层不动）
- 3000 仍在 8000 token 预算内（实测 skill 段+契约+工具 schema 总 <5K）
- 断言测试：code_stage 任务 prompt 必含"执行纪律"且含"src/"措辞（修订单验收清单第一条的加严版）
