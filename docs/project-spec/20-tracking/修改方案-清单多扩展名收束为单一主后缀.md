# 修改方案：清单多扩展名收束为单一主后缀

> 版本：2026-10-29  
> 前置：认领必成与源码清单纠偏（SYS-127～132）；计划期过载拆分与令牌 Stop（SYS-118～126）  
> 状态：已实现（SYS-133，2026-10-29）  
> 拍板：方案 **B**（从清单真源收束；本轮**不**改令牌 Stop 的 AND 语义）  
> 触发实测：`任务图构建_d4处理` FAILED —— 清单 d4「系统原型图」`ext:[.png,.jpg,.pdf]` 展开为三枚 `ext:*` 令牌，Stop 要求三种都有；32 轮内未写出 `.jpg` → Grace → FAILED  
> 原则：  
> 1. **验收意图是「任一可接受格式」时，进令牌前不得保留多种等价扩展名并列**，否则现网令牌 Stop 会变成「全都要」。  
> 2. **Runtime 确定性收束是唯一硬保障**；抽取提示**不**限制 AI 是否写多种图格式。  
> 3. 不按节点加工具轮次；不关 Grace；不改用户 skill。  
> 4. 与源码 zip 纠偏（SYS-128）同层：`validate_manifest` 归一化。

---

## 一、问题定性

| 层 | 行为 | 后果 |
|--|--|--|
| 清单抽取 | 原型图/流程图常写成 `ext: [.png, .jpg, .pdf]` | 把「任选一种图格式」写成了多后缀并列 |
| 令牌展开 | 每个 `ext` 一枚令牌 | load 虚高；Stop 要齐三种文件 |
| Worker | 易写出 `.png`/部分 `.pdf`，`.jpg` 难写或失败 | 32 轮用尽仍缺后缀 → FAILED |

现网 `check_match` / 冻结脚本对 `ext` 是「命中列表中任一」；**令牌 Stop 对持有的每枚 `ext:*` 却是合取**。本方案选 B：不改 Stop，改真源，使并列等价后缀在进认领/拆分前收成**一个主后缀**。

---

## 二、目标

1. 对「可互相替代的媒体/图类后缀组」，清单项 `match.ext` 在归一化后**至多保留 1 个**主后缀（V0.1 优先 `.png`，其次列表中第一个非次选）。  
2. **抽取提示不限制** AI 是否并列多种图格式（由模型自决）；收束只在 Runtime 归一化做。  
3. 收束可观测（如 `coerced_ext_singleton: true` 或日志）。  
4. 明确**不**改：令牌 Stop AND 语义、`_TOOL_ROUNDS`、Grace、过载阈值。

---

## 三、方案总览

```
抽清单 LLM（提示不限制图类是否多 ext）
  → validate_manifest
       ├─ 已有：源码类禁纯 zip（SYS-128）
       └─ ★ 新媒体组：等价后缀多选 → 收束为单一主后缀
  → 认领 / 令牌展开 / Stop（语义不变，但 ext 令牌变少）
```

---

## 四、收束规则（确定性）

### 4.1 等价后缀组（V0.1）

| 组名 | 成员（小写，带点） | 主后缀（优先保留） |
|--|--|--|
| 位图/原型图 | `.png` `.jpg` `.jpeg` `.webp` `.gif` `.bmp` | `.png` |
| 矢量/图示（可选同组或并入上组） | `.svg` | 若与位图并列 → 仍优先 `.png`；若仅有 `.svg` → 保留 `.svg` |
| 文档页式图 | `.pdf`（仅当与位图组**同时出现**时视为「可选替代」） | 与位图并列时**丢掉 `.pdf`**，保留位图主后缀；单独只有 `.pdf` 则保留 |

说明：实测失败项是 png+jpg+pdf 并列。「pdf 与位图同时出现」时把 pdf 当替代格式丢掉，避免一张「原型图」被要求三种文件。

**不收束的情况：**

- `ext` 只有 1 个；或  
- 后缀分属不同「产品形态」（例：`.pptx` + `.md`、`.py` + `.md`）——**不**用本组规则合并；保持原样。  
- 源码默认集合（SYS-128）不走本组。

### 4.2 算法

对每个 deliverable 的 `norm_match.ext`：

1. 若 `|ext| ≤ 1` → 跳过。  
2. 令 `bitmap = ext ∩ 位图组`，`has_pdf = .pdf ∈ ext`。  
3. 若 `|bitmap| ≥ 2`，或 `|bitmap| ≥ 1 且 has_pdf`：  
   - 主后缀 = `.png`（若在 bitmap/原列表中）否则 bitmap 中按稳定优先级下一档（`.jpg` → `.jpeg` → `.webp` → `.gif` → `.bmp`）否则原列表首个位图；  
   - `ext` 改为 `[主后缀]`；  
   - 打标 `coerced_ext_singleton: true`；记日志。  
4. 其它多后缀组合 → 不改（留给后续方案 A 或专项规则）。

### 4.3 抽取提示

**不做限制。** 不向 `extract_manifest_from_materials` 增加「图类只能一种 ext / 禁止 png+jpg+pdf」类提示；并列哪些后缀由 AI 自决。  
主保障仅为 §4.2 的 Runtime 收束。

## 五、明确不做

- 用抽取提示限制图类 `ext` 写法（本轮明确取消）。  
- 修改令牌 Stop「多枚 ext 合取」语义（那是方案 A；本轮不做）。  
- 为图类节点提高 `_TOOL_ROUNDS`。  
- 按扩展名强制再拆节点（方案 C）。  
- 改用户 skill。

---

## 六、验收

1. 合成项：`name=系统原型图`，`ext:[.png,.jpg,.pdf]` → 归一化后 `ext:[.png]`，且 `coerced_ext_singleton`（或等价标记）为真。  
2. `ext:[.pdf]`  alone → 不改写。  
3. `ext:[.py,.md]` → 不按本组改写。  
4. 回归：源码纯 zip 纠偏（SYS-128）仍绿。  
5. 抽取 prompt **不含**「图类禁止多 ext」类约束（单测或快照断言）。  
6. （手工）重规划后 d4 类节点令牌不再含三枚 `ext:*`；Stop 只需一种图文件。

## 十、残余风险

| 风险 | 说明 |
|--|--|
| 材料硬性要求「同时交 png 与 pdf」 | 收束后只验一种；应拆成两个清单项——提示已引导 |
