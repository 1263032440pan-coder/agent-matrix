# 设计单 V1.6b：交付收工硬闸（Claude Stop 对齐）

> 版本：V1.6b（2026-10-27）  
> 背景：V1.6 收工自查在 `_execute_llm` **之后**拼字，模型同轮看不见 → 主任务可 ACCEPTED 而三件 ❌。  
> 用户决策：对齐 Claude Stop hook；**修复轮次 3**；用尽仍缺 → **任务直接 FAILED**。

## 语义

| Claude | 本项目 |
|--------|--------|
| Stop 前跑校验 | 工具循环「无 tool_calls、拟终稿」出口 |
| exit 2 喂回继续 | 注入 user 返工消息，`continue` 循环 |
| 修到过关才停 | 校验通过才 `_archive_session` |
| （脚本常硬失败） | 3 次仍缺 → `DeliveryBaselineError` → Worker `success=False` → Task **FAILED** |

校验范围（存在性，与收口/BackfillValidator 同口径）：工作区文件树  
- `ppt`：有 `.pptx`  
- `code`：有 `.py/.js/.ts/.java` **且** 有 `readme*`  
- `test_report`：文件名含「测试」且 `.md`

触发：`delivery_tags` 非空，或 `code_stage`（并入 `code`）。无 tags 不拦。

## 改动点

1. `llm_worker.py`：循环内硬闸 + 3 轮返工；删除循环外假自查依赖（或改为 no-op）  
2. `service.py`：收口补建 `promote_to_ready` 后 **`submit`**，避免 READY 挂死  
3. 测试：`test_delivery_stop_gate.py`（拦截/补齐通过/3 次 FAILED）

## 非目标

- 不引入外部 `.sh` hooks  
- 不把 PPT≥6 页等质量细则再硬编码进硬闸（仍靠 skill + 既有 ppt 读回 / 补建 Gate）
