## 背景

D18 收官后为实链路联调（LLM 配置 → 创建项目 → 导入 md → 生成计划 → 执行项目）新增 8 个端点，全部走既有架构边界（WorkerAdapter / NormalizerExtractor Protocol / with_llm opt-in / FSM），无红线偏离，但接口规范欠账。按返修单-D18后增量改动-偏离检查 问题 2 整改。

## 约束明确

### `/execute` 职责边界

`/execute` 只做**一次 dispatch 扫描**（Scheduler.dispatch_once），不负责循环推进；执行深度 = 当前 READY 任务全集。V0.1 同步长事务（全部跑完才返回），实时进度依赖轮询刷新；正式阶段由 Event Engine（WP-011）替代。

**处置（RH-01 前置 2，方案 A）**：V1.13 起 `/execute` 改为薄封装——内部创建 Execution 走 WP-040 异步通道，返回 202 + execution_id，与 `POST /api/executions` 行为一致；同步阻塞语义废弃。

### `/mode` 切换约束（V0.1 显式放开）

- V0.1 无 FSM 规则阻断运行时切换（RUNNING 任务存在时也可切换，只影响**下一次** dispatch 行为，不回溯已 RUNNING 任务）。
- 已知风险：RUNNING 中切 MANUAL 不会中断执行中任务——登记为已知放开，正式阶段由 Gate/Checkpoint 补约束。
