# 修改方案：义务驱动工具绑定与规划期矛盾消解

> 版本：2026-11-02  
> 前置：Agent 白名单（V1.4）；`BINARY_SUFFIX_DENIED`（office 受控后缀）；交付认领 / obligation_tokens；软放行（SYS-138～140）  
> 触发：任务掉入 `misc` 通用体（仅 `file_rw`+`web_search`），却挂 `.pptx` 义务 → `write_file` 合法拒写 → 模型空转至预算耗尽/软放行  
> 参考：DeepSeek `dsh-superagent-prototype`（Router/Worker 能力分离、工作单绑工具）——**仅借鉴思路，不照搬 Ticket/Harness 壳**  
> 状态：**已落地**（2026-11-02：obligation_plugins / 执行前门禁 / 规划期消解 / Dashboard 对照 / 别名辅补）  
> 修订：矛盾消解覆盖办公+位图（非仅 PPT）；认领顺序改为 **消解 → 过载拆分 → 整闸**，禁止消解后提前整闸。

---

## 一、问题

1. **环节名掉格**：`task_type`（如「功能实现」）未落入九环节 → `normalize_stage` → `misc` → 「通用任务智能体」窄白名单。  
2. **义务与能力脱节**：节点 `obligation_tokens` 要求 `.pptx`，但 Agent plugins 无 `office_pptx`。  
3. **计划/认领自相矛盾**：`delivery_tags=code` / 源码产出，却认领纯 `.pptx` 义务。  
4. **拒写后无闭环**：`BINARY_SUFFIX_DENIED` 后模型反复用 `write_file` 试探，耗尽工具预算再软放行，表象为「没有其他可用工具」。

根因不是「没创建智能体」，而是 **派了无 PPT 权限的体 + 源头义务/标签不一致 + 执行期缺纠偏**。

---

## 二、拍板结论

| # | 结论 |
|--|--|
| 1 | **主门禁 = 义务驱动工具**；环节别名仅为辅，**不得**作为唯一依据（防漏检） |
| 2 | 「标签像代码、义务却是纯 pptx」等矛盾必须在 **规划/认领阶段** 拆任务或改认领；**必须保证流程图（Task Graph）最终生成** |
| 3 | 执行期纠偏 **不改流程图**（不增删改节点拓扑）；只做工具提示 / 改绑 Agent / BLOCKED |
| 4 | Dashboard 展示：本节点 **绑定 Agent + 插件** vs **义务所需插件**（缺口标红） |
| 5 | 保留 `write_file` 对受控后缀的拒写；不放开假二进制写入 |

## 三、名词

| 名词 | 含义 |
|--|--|
| **义务** | `obligation_tokens` / 认领交付物所隐含的受控后缀（如 `.pptx`） |
| **所需插件** | 由义务映射出的工具裸名集合（如 `office_pptx`） |
| **能力缺口** | `所需插件 − expand(Agent.plugins)` |
| **规划期消解** | 在出图/认领阶段拆节点或改 `deliverable_ids`，消掉标签↔义务矛盾 |
| **执行期纠偏** | 拒写提示、改绑、BLOCKED；**不** Replan 画布 |

## 四、方案分块

### 4.1 义务 → 所需插件（主路径）

纯函数（建议 `project_runtime/worker/obligation_plugins.py`）：

```text
required_plugins_for_task(playbook_ref | tokens | deliverable_ids+manifest) → set[str]
```

映射（V0 最小集，可扩展）：

| 义务信号 | 所需插件 |
|--|--|
| 扩展名 / 令牌涉及 `.pptx` | `office_pptx` |
| `.docx` | `office_docx` |
| `.xlsx` | `office_xlsx` |
| `.pdf`（受控办公 PDF） | `office_pdf` |
| 位图槽 `.png/.jpg/.jpeg/.webp` | `image_raster` |

**执行前门禁**（`lifecycle` 选体之后、Worker 进工具循环之前）：

1. 算 `need`、`have`  
2. `gap = need - have` 为空 → 放行  
3. 非空时按序：  
   - **改绑**到同项目已有且 `need ⊆ plugins` 的实例/模板；  
   - 否则对 Controller 派生模板在 `SAFE_INCREMENT_PLUGINS` 内 **补齐**后绑定；  
   - 仍无法满足 → 任务 **BLOCKED**（缺能力），文案列出缺口；**禁止**带着缺口进工具循环磨预算  

环节别名补全（`STAGE_ALIASES`）可作为降低 misc 概率的辅措施，**显式标为非充分条件**。

### 4.2 规划期矛盾消解（保证出图）

**冲突判定（示例）：**

- 意图偏代码：`delivery_tags` 含 `code` 且无 `ppt`，或 `stage_outputs` 主语义为源码/实现；  
- 义务偏办公：义务后缀集主要为 `.pptx`（或仅办公后缀、无代码类扩展）；  
- → 判为 **CODE_PPT_MISMATCH**（可扩展其它标签↔后缀矩阵）

**处置（已拍板）：**

1. 在 **规划流水线认领阶段或紧前** 检出；  
2. **自动消解**（优先）：  
   - **拆任务**：保留代码节点义务为代码类；新建/调整「交付补全-PPT」类节点认领 `.pptx`；依赖边合理挂接；或  
   - **改认领**：若节点本意即 PPT，改 `delivery_tags`/产出描述与义务对齐，并确保后续会绑到含 `office_pptx` 的体；  
3. 消解后 **必须** 产出完整、可执行的 Task Graph（流程图最终生成）；  
4. 仅当自动消解失败 → `422` + problems（不得静默留下矛盾 READY 节点）

**不做：** 执行中途改 Playbook/拆图冒充消解。

### 4.3 执行期纠偏（不改流程图）

当 `write_file` / `append_file` 返回 `BINARY_SUFFIX_DENIED`：

1. **工具结果文案**必须包含：  
   - 禁止用该工具写此后缀；  
   - **请改用**对应 `office_*` / `image_raster`（写出工具名）；  
   - 本 Agent **当前可见工具列表**（或明确「当前无 office_pptx」）  
2. 若本 Agent **没有**对应插件：  
   - 触发与 4.1 相同的 **改绑**；失败则 **BLOCKED（缺能力）**；  
   - **不得**继续空转至工具预算耗尽再软放行（缺能力 ≠ 交付软缺口）  
3. 若有对应插件：仅提示纠偏，由模型下一轮改调正确工具；可对「同后缀错误工具 ≥N 次」加强制 nudge  

**明确：执行期纠偏 = 提示 / 改绑 / BLOCKED，不是改流程图。**

软放行仍只用于「有能力仍交不齐文件」等既有缺口语义，与「根本无工具权限」分离。

### 4.4 Dashboard 对照

节点详情（或任务侧栏）增加只读块：

| 展示项 | 来源 |
|--|--|
| 绑定 Agent 名 / id | 当前实例 |
| 当前插件列表 | definition.plugins 展开 |
| 义务所需插件 | 4.1 纯函数 |
| 缺口 | 差集，非空时醒目标记 |

API：dashboard task 字段增补 `bound_agent`、`agent_plugins`、`required_plugins`、`plugin_gap`（命名以实现为准）。

## 九、风险与回滚

| 风险 | 缓解 |
|--|--|
| 改绑抖动 / 抢实例 | 优先空闲实例；失败 BLOCKED 优于错体执行 |
| 拆任务改变用户预期拓扑 | 消解规则写清；事件审计；Dashboard 可见 |
| BLOCKED 增多 | 与「假 ACCEPTED」相比可接受；配一键用户 Rework/改绑入口 |
| 回滚 | 关闭执行前门禁与规划消解开关（若加 feature flag）；保留拒写 |

## 十、与 DSH 原型的借鉴边界

| 借鉴 | 不借鉴 |
|--|--|

| 做不了就 blocked，而非假完成 | 其 Feishu/合并策略 |
