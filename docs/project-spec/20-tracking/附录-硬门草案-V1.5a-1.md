## 硬门语义（替代软提醒的强制版）

```
Worker 完成 code_stage 任务时:
  ① 强制 test_runner 一轮:
     - 检测工作区测试文件（tests/ 下 *.py / *.test.js）
     - 无测试文件 → 视为未满足契约 → 喂回: "契约要求测试文件, 请补写后重试"
     - 有 → shell 跑 pytest（test_runner 插件, 白名单已含）
  ② 结果二分:
     - 通过 → 正常收工（产物含测试报告摘要）
     - 失败 → 失败输出（退出码/失败用例名/错误摘要）喂回:
       "测试未通过: {失败摘要}。请修复代码使测试通过后重新交付。"
       模型在同一工具循环内继续或触发任务重写
  ③ 防死循环:
     - 修复重试上限 2 次（独立计数, 不占 12 轮工具预算——
       反馈环是收工前的独立校验循环）
     - 2 次仍失败 → 按契约如实交付"测试未通过"报告
       （REWORK 升级交 Gate——Gate FAIL→REWORK 链既有）
     - 不自动降低测试标准（防"删测试保通过"——测试文件写定后
       本环节只跑不改）
```

## 与软提醒的关系

启用硬门后**软提醒保留**（它拦的是"根本没写测试"，硬门拦的是"测试没跑通"）——两层并存：软提醒（一次性提示）→ 硬门（强制 2 次修复）→ Gate REWORK（终审）。
