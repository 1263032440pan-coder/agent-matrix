# 修改方案：交付类型槽与相对路径验收

> 版本：2026-10-29  
> 前置：SYS-118～133（令牌 Stop / 认领必成 / 媒体 ext 收束）  
> 状态：已实现（SYS-134～137，2026-10-29）  
> 拍板：用 **类型槽 + 约定相对目录** 替代「文件名中英子串」硬闸（不再做同义词表）  
> 触发：`项目理解` FAILED——内容已有 `requirements-*.md` / `architecture-*.md`，令牌要求文件名含「需求」「架构」，改名空转耗尽 32 轮  

> 原则：  
> 1. 验收看「是否落到约定槽目录」，不看文件名是否等于清单中文针。  
> 2. Runtime 确定性收束：旧 `name_contains` 可映射为 `slot`；有 `slot` 后不再展开 `name:` 令牌。  
> 3. 槽内文件名自由（中英缩写均可）；内容正确性仍不由本闸保证。  
> 4. 不改 Stop 合取、不改 `_TOOL_ROUNDS`、不改用户 skill。  

---

## 一、契约（V0.1）

`match` 新增：

| 键 | 含义 |
|--|--|
| `slot` | 类型槽 id（snake_case），如 `requirements` / `architecture` |
| `rel_dir` | 相对任务目录的槽目录，默认 `deliverables/{slot}` |

约定：任务目录下 `deliverables/{slot}/` 内 **≥ min_count** 个普通文件即过该槽（可再叠加 `ext` 过滤）。

针 → 槽映射（validate 收束用）：

| name_contains / 名称含 | slot |
|--|--|
| 需求 | requirements |
| 架构 | architecture |
| 原型 | prototype |
| 流程图 | flowchart |
| 解决方案 | solution |
| 开发 | development |
| 测试 | testing |
| 理解 | understanding |

纯源码类（有 `ext`、无文档针）可不设 slot，仍走 ext/prefix/count。

---

## 二、链路

```
抽清单（提示引导写 slot）
  → validate_manifest：name_contains → 补 slot+rel_dir；有 slot 则去掉 name_contains（防双闸）
  → 令牌展开：slot:{did}:{slot}（有 slot 不展 name:）；count 按槽内计数
  → 令牌 Stop：本任务目录 deliverables/{slot}/
  → 清单 Stop / 冻结脚本：工作区相对路径含 deliverables/{slot}/
  → Worker 上下文：提示必须写入 rel_dir
```
